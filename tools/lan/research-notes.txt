Native confirmation from parallel disassembly (preferred over Lua inference)
- SessionGetDiscovery(arg1 bool) chooses LAN vs Online via EDA320.
- HE SessionJoin binding at 84F050/84F070 reads the LAN bool from Lua ARGUMENT 3.
  The staged call is consequently SessionJoin(ID,false,lanMode), with existing
  online invitation calls left untouched.
- The LAN Join target at EF8E00 is a success-returning stub (mov al,1; ret4).
  A successful Lua return from Join is NOT proof of joining a peer.
- Native LAN Create still requires LoginGetter ED7230 and NAT readiness ED7270.
  Lua UI gates alone cannot make offline LAN work.

Scope of the research delta
- Adds explicit LAN diagnostics (not playable) menu entry; exposes Online/LAN filter.
- Accepts an explicit lanMode and keeps it through creation/host/join UI.
- Routes discovery and browser join using the verified native boolean positions.
- Bypasses Lua login, NAT, and RDV UI gates only in the LAN workflow.
- Keeps online QuickMatch and Ubisoft invitation paths out of LAN workflow.
- Disables LAN Join because the native implementation is a success-returning stub.
  Its argument-position delta is recorded for correctness, not exposed as working.
- Keeps native SessionIsInSession, ready state, slot synchronization and StartGame.
- Keeps native start events: StartGame -> receivedStartGameMessage ->
  state.restartWithMultiplayer -> boot.startMultiplayer -> multiplayer load screen.
- Does not fake discovery completion, peer identity, readiness, or session success.
